# `parity-cases.v1.json` — the cross-repository text-identity contract

This fixture is the contract for the single notion of text equality in PricePulse (ADR-012 **D7**).
It is consumed by a contract test in **each** repository:

| Repository | Implementation under test | Contract test |
| --- | --- | --- |
| PricePulse-backend (this one) | `MarketTextKey` | `MarketTextKeyParityTest` |
| PricePulse (app) | `ProductNameMatchKey` | app-side contract test against its byte-identical copy |

The backend cannot import `ProductNameMatchKey`: it lives in the app, has a private constructor, and
the two repositories are built independently. So the backend reimplements the **rule**, never the
type, and this fixture turns any divergence into a red test instead of a silent wrong merge.

## Provenance

Every expected value was generated by invoking the **compiled app class** `ProductNameMatchKey`
(PricePulse `c81a2d9`, source unchanged since `f18eaf2`) through reflection, with `kotlin-stdlib`
2.2.10. Only the inputs were written by hand; the outputs never were.

Both contract tests pin this value. The app copy must have the **same** hash: it is extracted from a

never from a working copy. LF normalisation is needed because the app repository uses
`core.autocrlf=true` while this one uses `core.autocrlf=false`.

## The fixture is never edited to make a test pass

**When a case fails, the implementation is wrong until proven otherwise.** Changing an expected value
requires regenerating it from the app and changing **both** copies and **both** pinned hashes
together, in one coordinated decision. Editing this file to turn a test green re-creates the second
notion of text equality that ADR-012 D7 exists to prevent.

## Encoding

Non-ASCII and control characters are written as `\uXXXX` escapes, so the file is pure ASCII and no
editor can silently change it.

## The behaviour this fixture pins

The app's rule applies **two different** notions of whitespace, and that is the whole contract:

1. `kotlin.text.trim()` at the borders — removes every character for which Kotlin's
   `Char.isWhitespace()` is true, **including** NBSP (` `), narrow NBSP (` `) and figure
   space (` `). It is **not** `java.lang.String.trim()` or `strip()`, neither of which removes
   them.
2. `Regex("\\p{javaWhitespace}+")` collapses internal runs to a single space — and
   `\p{javaWhitespace}` does **not** match NBSP, narrow NBSP or figure space.

Consequences pinned here:

- border whitespace, **including NBSP**, is removed;
- **internal** NBSP, narrow NBSP and figure space are **not** collapsed;
- zero width space (`​`) is **never** removed, at a border or inside, and a ZWSP-only text is
  **accepted**;
- text made only of removable whitespace is **rejected**;
- case folds under `Locale.ROOT`; accents are preserved; **no Unicode normalization** is applied, so
  precomposed `é` differs from `e` + `́`.

**This is the real, current behaviour of the app — not a legacy quirk to be preserved.** The earlier
`LEGACY_CANONICAL_BEHAVIOR` classification of border whitespace was withdrawn on 2026-09-17 after the
Milestone 5 assumption audit established the real behaviour from the compiled class.

## `INTERNAL_NBSP_NORMALIZATION`

That internal NBSP, narrow NBSP and figure space are not collapsed is registered future debt:
`INTERNAL_NBSP_NORMALIZATION` = **FUTURE / NOT_DECIDED**. It **must never be applied locally**. Any
future change to the key would reshape every stored alias (ADR-012) and would have to be versioned
and applied to the app and the backend together. Source-side sanitisation of NBSP and HTML entities
belongs to the adapter boundary (S9), never to this identity rule.
